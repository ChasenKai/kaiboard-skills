# 素材库实战配方 / Library recipes

> 本文补 `SKILL.md` §素材感知构图的**落地细节**。
> 来源：2026-09-21 ~ 22 首次真正跑通全链路（KaiBoard 概念图），把踩到的坑与验证过的布局固化成配方。

## 一、取件的四步

```bash
python scripts/lib_resolver.py --search "<词>"          # 跨源检索（232 库 / 159 带组件索引）
python scripts/lib_resolver.py --ensure "<库名>"        # 下载并沉淀到 scripts/libs/
python scripts/lib_resolver.py --components <lib> <名>  # 取组件 → 画板元素（或自行读 .excalidrawlib）
python scripts/lib_resolver.py --list-my                # 看已缓存
```
数据源：`excalidraw/excalidraw-libraries`（官方）→ `libraries.json` + `libraries/<source>`。

**检索心法**：用**具体名词**搜（`robot` / `server` / `database` / `it`），不要用组合短语
（`"ai agent"`、`"database storage"`、`"browser window"` 一律 **0 命中** —— 索引是「库名 + 组件名」的模糊匹配）。

## 二、🔴 复用组件的三个坑（都踩过）

### 1. 两种文件格式都要兼容
| 版本 | 字段 | 形状 |
|---|---|---|
| **v1** | `library` | **元素数组的数组**（没有组件名）|
| **v2** | `libraryItems` | `[{name, elements}]` |
→ 读取时 `d.get("libraryItems") or d.get("library")`，并对 v1 用 `item0/item1…` 兜底命名。
（实测：`kaligule/robots` 是 **v1**。）

### 2. 组件自带英文标签，用时必须丢掉
库组件常带 `text`（如 `User`、`Server`）→ 直接用会**中英混排**。
→ 落板前 **过滤掉 `type == "text"` 的元素**，标题自己写。

### 3. 落板前的归一化（四件事）
```python
# ① 坐标归一化到左上角（各组件原点不同）
# ② 重置 id（避免与画板已有元素撞）
# ③ 清空 groupIds / frameId（避免继承陌生分组）
# ④ 修 containerId / boundElements 里的旧 id 引用
```
**还有**：`points`（line/arrow 的相对坐标）在缩放时**要一起乘 scale**，否则线会错位。

## 三、🔑 布局：图标放卡片**右侧**，文字占**左侧**

这是验证下来最不容易翻车的卡片结构（Kai 提供的参考图也是这个路子）：

```
┌───────────────────────────────────────────────┐
│  标题（左对齐）                            [图标] │
│  说明（左对齐，可多行）                          │
└───────────────────────────────────────────────┘
```

**为什么**：图标插在「标题与说明之间」会把文字挤到很窄 —— 实测 270px 的卡片装不下
「IndexedDB · 自动保存 · 无账号」这类串，**必然溢出**。

**若文字仍然长**：
1. 卡片改**通栏**（堆叠），不要并排
2. 或**缩短文案**（主标题短、细节下移副行）
3. ❌ 不要靠缩字号硬塞

## 四、🔴 出图前**先跑自检**，别靠肉眼

```bash
python scripts/geometry_check.py <board.excalidraw>   # 穿框 / 重叠 / 悬空绑定 / 重复 id
```
**教训**：本轮两次「文字溢出卡片」都是**肉眼**看出来的（改了 3 轮才对）。
`geometry_check.py` 就是为这类问题准备的 —— **先跑它，再看图**。

## 五、风格档位：按图的"性格"分，不是一刀切

| 图的性格 | `roughness` | 例 |
|---|---|---|
| **讲结构 / 讲边界**（架构图、参考架构）| **0（非手绘）** | 「KaiBoard 参考架构」—— 框线与箭头要精确 |

## 七、🔴 组件尺寸差异巨大 → 必须**按容器自适应缩放**（fit）

**踩坑实况**：把库组件直接塞进卡片 → **溢出卡片**。
Go 吉祥物 / 小鸡 / 火柴人 / 工具箱的原始尺寸各不相同（有的近 200px），自己手算 scale 必然翻车。

**正确做法**：写一个 fit 函数，先量组件真实外接矩形，再等比缩放到容器内并居中：

```python
s  = min((bw - pad*2) / comp_w, (bh - pad*2) / comp_h)   # 等比缩放到"装得下"
ox = bx + pad + ((bw - pad*2) - comp_w*s) / 2            # 水平居中
oy = by + pad + ((bh - pad*2) - comp_h*s) / 2            # 垂直居中
# 逐元素：x / y / width / height 一起乘 s；points 也要乘 s
```

**三个要点**：
1. **先量后缩**，不要凭感觉给 scale
2. 卡片内容区要**明确留出标题+副标题的高度**（如内容区从 `y+100` 起、高 = 卡高 − 120）
3. 放完**跑 `geometry_check.py`**，或**先出一次图看**，别等交付才发现

> 同理：**多个组件并排**时，用「**等宽格子 + fit**」而不是固定 x 偏移 —— 否则某个偏宽的组件会把邻居挤出去。
