# KaiBoard Agent 共绘 · 自服务设置指南（一页）

> 本地优先白板 + Agent 共绘：KaiBoard 页面 ↔ 本机统一中继（内建于 MCP 进程）↔ 你的 Agent。画布数据不上云，共绘指令只在本机 127.0.0.1 流转。

## 核心模型（一句话）

开关 ON = 在 KaiBoard 设置里「释放」一个**中继令牌**；你把它**复制**出来，粘进你所用 Agent 的 MCP 配置（`KAIBOARD_TOKEN`）。**给谁令牌 = 授权谁共绘；不给 = 任何 Agent 都不能动你的画布。**

（不是 Agent 自动发现——令牌必须由你手动复制、手动授权。）

## 这部分跟你有关吗？（适用范围）

- **如果你只是用 KaiBoard 做多画板管理、手写、文件树整理等常规功能**：本指南的「中继 / 令牌」全部与你无关。那些功能纯前端、本地优先，打开网页即用，不需要任何额外程序。
- **只有当你想让 AI Agent 在你的画布上实时共绘（增删元素）时**，才需要本指南的「MCP 包 + 令牌」这一步。不开「Agent 共绘」开关，就完全不碰这一块。

## 你自己的电脑：最短 4 步

1. **打开 KaiBoard 网页**，进入**设置**，把 **Agent 共绘** 开关拨到 **ON**。
   - 只有要「让 Agent 在画布上实时增删元素」时才需要这一步。只用多画板 / 手写 / 文件树等常规功能的话，整节都可跳过。
2. **在同一处点「复制给 Agent」** —— 一键拿到一段**可直接粘给你的 AI 助手**的配置（含 MCP 服务端地址与你的令牌）。
3. **把这段发给你的 AI 助手**，让它照着配好 MCP（`@kaibuddy/kaiboard-mcp`，`--relay` 模式）。
   - 该进程**内建本机中继**，无需再单独启动任何 `.exe` / 脚本 / 守护进程。
4. **回到 KaiBoard 面板确认显示「连接成功」**。完成 —— 你的助手现在能在你开着的画布上实时增删元素。

> **为什么说"已经帮你省事了"**：令牌本身必须由你授权（见下节），但**取令牌 → 拼配置 → 告诉助手怎么做**这三件事被压成了**一次点击 + 一次粘贴**。
> 若你的助手支持 Agent Skills，还可以让它一并装上配套技能，以后"怎么画"它也懂 —— 见本仓 README。
## 撤销 / 换令牌

- 把开关 **OFF** → 令牌立即作废，任何 Agent 都连不上。
- 同一台机器**重启 MCP 会复用上次持久化的令牌**（稳定不变，不用每次重配）；只有**删除令牌文件或换了一台全新机器**才会生成新令牌 → 重新走第 3–4 步复制粘贴即可。

## 换一台电脑 / 给别人用（全自助）

1. 对方在自己机器上装好 `kaiboard-mcp`（统一包，`--relay` 模式），并让 KaiBoard 跑起来。
2. 对方打开 KaiBoard → 开 Agent 共绘 → 复制中继令牌 → 粘进**他自己** Agent 的 MCP 配置（`KAIBOARD_TOKEN`）。
3. 全程 < 1 分钟，**不需要装 Node、不需要命令行、不需要任何人工介入**（MCP 客户端会自己拉起 `kaiboard-mcp` 进程）。

> 每台机器的中继令牌各自独立生成；换机器要重新复制一次（这是本地优先架构的天然属性，不是缺陷）。同一台机器重启 MCP，令牌保持不变，不用反复配。

## 开机自启（可选，自己电脑一劳永逸）

`kaiboard-mcp` 由你的 MCP 客户端在需要时对 `--relay` 条目自动拉起，**无需手动常驻**。若你希望它随系统启动，把 MCP 客户端设为开机自启即可，不必单独管理中继进程。

## 安全边界（必读）

很多人看到「Agent 能改我画布」会担心。这里把来龙去脉说清楚。

### 为什么放心？

- **本地优先**：画布数据存你浏览器本地（IndexedDB），**不上云、不建账号、不外传**。
- **Agent 交互必须本机回环**：浏览器按 origin 隔离，Agent 端没法直接碰你网页里的画布；要打通，必须有一个「待在你本机、只听 127.0.0.1 的中继」在页面客户端和 Agent 之间转发指令。出于安全，它**只能是本机回环，绝不能暴露到公网**。
- **统一中继内建于 `kaiboard-mcp` 进程**：不再有独立的 `.exe` 便携中继文件，中继与 MCP server 是同一个 node 进程（由你的 MCP 客户端拉起，来源 = `@kaibuddy/kaiboard-mcp` 统一包，源码随 npm 包公开、可审）。

### 它到底在做什么 / 不做什么

- ✅ **只做一件事**：在本机 `127.0.0.1:8787` 上，把 Agent 发来的「增 / 删元素」指令转发给开着的 KaiBoard 页面，再把页面响应转回 Agent。纯内存中转，指令一进一出即丢，不落盘。
- ❌ **不读你的任何文件**（不扫盘、不碰文档 / 图片 / 画板文件）。
- ❌ **不连外部网络**（只绑 127.0.0.1，外网不可达；没有任何出站请求、不上传任何数据）。
- ❌ **不执行任意代码**（只认固定的 getBoard / addElement / replaceBoard 等指令，不运行 Agent 传来的脚本）。
- ❌ **不改系统、不提权、不自启**（除非你把 MCP 客户端设为开机自启）。
- ❌ **没有隐藏常驻**（没有后台服务、没有计划任务，进程在就在，不在就不在）。

### 为什么令牌要由你手动授权（而不是自动发现）？

这是一个**未做代码签名的开源工具**。显式令牌模型（`KAIBOARD_TOKEN`）的意义是：**没有你的显式授权，任何 Agent 都连不上你的画布** —— 开关始终在你手上。

**但"手动"不等于"麻烦"** —— 我们把容易出错的环节都收进了一次点击：
- 令牌不用你去找、去拼：**面板「复制给 Agent」一次给你一段完整、可直接粘的配置**；
- 不用你猜怎么写 MCP 配置：那段里已经写好了服务端包名与启动参数；
- 不用你记"还要装什么"：若你的助手支持 Agent Skills，它会顺带把配套技能也装上。

> 取舍说明：**便利 vs 本地优先**，我们选了后者 —— 代价是你多点一次授权，换来的是"没你点头就别想碰你的画布"。

### 如果你仍不放心

源码与协议随 `@kaibuddy/kaiboard-mcp` 一并公开（npm 包内含源码），可交给任意安全人士审查。

## 安全边界（运行时）

- 中继只监听 `127.0.0.1`（本机回环），外部网络不可达。
- 没有令牌 / 令牌不符的请求一律 403 拒绝。
- 共绘指令只在本机中转，**不过云**（符合 KaiBoard「本地优先、数据不上行」承诺）。
- 敏感动作（整板替换）在 KaiBoard 侧有 toast 透明提示，你看得见。

## 常见问题

- **MCP 已注册但 KaiBoard 显示「未连接」？** 检查：① 开关是否 ON；② 令牌是否一致（重启过 MCP 会复用旧令牌，无需重配；只有换机器 / 删令牌文件才换）；③ `kaiboard-mcp` 进程是否真的在跑（看 MCP 客户端里该连接的状态）。
- **想要云端中继、完全不用本机进程？** 当前为本地中继设计。若以后需要零本地进程，可把中继搬到托管服务，但共绘指令会过云——属「便利 vs 本地优先」取舍，按需再定。
- **我有两台自己的电脑（MCP 配置会同步），令牌怎么管？** 每台机器各自生成独立令牌（同一台重启后令牌稳定，不用反复配）。由于中继只绑 `127.0.0.1`，Agent 必须和运行 KaiBoard 的机器**同一台**才能驱动它——若你的 MCP 配置在多台机器间同步，可在其中注册**两个** `kaiboard-mcp` 条目（`kaiboard-mcp-a` 填机器 A 的令牌、`kaiboard-mcp-b` 填机器 B 的令牌，端口都用默认 `8787` 即可）。因为每台机器的中继只接受**自己的**令牌（不符一律 403），所以在机器 A 上时只有 `-a` 连得上、`-b` 自动 403 失败；在机器 B 上时反过来。等于「同一份 MCP 配置里记了两台机器的令牌，当前在哪台就自动用哪台的」，无需手动切换。若你的客户端配置**不**跨机器同步，直接各配各的即可。两台电脑画布数据各自本地独立（IndexedDB），不会互相干扰；只有当你主动在机器间导出 / 导入画板文件时才会交汇（文件级最后写入者胜）。
