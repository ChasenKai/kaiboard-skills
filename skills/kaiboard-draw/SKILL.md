# kaiboard-draw

在 KaiBoard 上作图。两种协作模式共用同一份「合法 Excalidraw 元素」契约。

## 路由：先判断走哪条

| 用户意图 | 模式 | 含义 | 指引 |
|---|---|---|---|
| 已打开 KaiBoard，要 Agent 在**当前画布实时增删改** | **Mode A · 共绘（首选）** | 经 MCP 驱动已打开的 KaiBoard 画布 | → `references/mode-a-codraw.md` |
| "画个框图/流程图/架构图"，拿到文件自己导入看 | **Mode B · 文件** | 本地生成 `.excalidraw`，KaiBoard 零改动 | → `references/mode-b-file.md` |

> **为什么 Mode A 是首选**：它直接作用于你眼前正在看的画布 —— 画完即见、可当场继续改，无需导入导出。Mode B 适合"离线产出、稍后再看/给别人"。

两种模式最终都收敛到**「合法 Excalidraw 元素」** —— Mode A 推元素、Mode B 出文件，源契约一致。

## 能力边界（先读，避免预期落差）

- **目标**：任何支持 Agent Skills 与 MCP 的客户端都能用。
- **实际验证情况**：目前主要在 **WorkBuddy** 上验证过。**其他客户端请自行验证与调教** —— 不同客户端的工具暴露方式、画板连接方式可能不同，属正常。
- **阶段**：早期 / 预览版，接口与内容可能变化，暂不建议用于关键流程。
- **遇到问题**：欢迎提 Issue。若某客户端行为与本文档不符，以该客户端的实际行为为准。

## 安全边界（要点，细节以 KaiBoard 侧说明为准）

- 数据不出本机：KaiBoard 无服务器、无账号，画布数据只在你自己的设备上。
- 共绘默认关闭；开启才生成令牌。**不要把令牌写进公开文件或分享给他人**。
- 令牌不匹配 / 来源不符时，本地中继一律不响应。

## 共同铁律（两种模式都遵守）

1. **合法优先**：产物必须是合法 Excalidraw 元素 / 合法 `.excalidraw` 文件，否则导入白屏（`appState.zoom` 必须是 `{value: number}` 对象；元素须含 `id/type/x/y/width/height`）。

2. **预览—确认—落板**：落板前先渲染**真实手绘风预览**给人确认。用与 Excalidraw 同款的手绘引擎（roughjs）渲染，**不要**用扁平结构 SVG —— 那会误导判断。

3. **源随图走**：写类操作带上 `source`（Mermaid / DSL / 用户原话），落到元素的 `customData.__kbSource`，避免"图变成黑箱、日后读不回"。

4. **落板目标默认是当前画板**：「推个图看看」默认落到你**当前打开的画板**，往下追加（非破坏）；原地重做同一张图时才整板替换。**只有用户显式说「新建画板」才新建**。绝不在"推个图"时默认开新板。

5. **批次标记（分隔符）每批必带**：共绘每批新增内容的**第一个元素**是一个「批次标记」文本框，格式固定 —— 分隔符 + 时间戳 + 批次号 + 一句话主题。它既把本轮新内容与画板其余内容分开，也是一份"谁画、何时画、画了什么"的传递记录。仅当用户明确说"不要批次标记"才跳过。

6. **落板意图三态 + 模糊先问**：用户说"画个图 / 推个图"时先判落板意图，指令不明就**在对话里先问一句**（新建画板 / 覆盖当前 / 当前板下方插入？），不急着生成：
   - **新建画板**：用户显式说「新建画板 / 单独一张」→ 新建（可基于旧板内容派生，旧板保留不动）。
   - **覆盖整板**：用户说「重做这张 / 替换 / 覆盖整板」→ 整板替换。**不是默认选项**，须用户明确点名。
   - **当前板下方插入**：默认方式 —— 新内容整批下移到已有内容下方并左对齐，便于新旧对比；历史不要的内容用户按需删即可。
   - **纪律**：改既有画板时**一般不直接覆盖**（防结果不如预期）；默认走"同板追加对比"。

7. **画板 / 文件夹的删除与新建有边界 —— 遇到就如实告知，不静默失败**：
   - **`deleteBoard` 不能删「当前打开着的画板」** → 返回 `cannot delete the currently open board; switch to another board first`。
     这是**设计约束**（防自删正在看的画板），**不是故障**。
     → **不要静默失败、不要反复重试**。向用户说清 **两件事**：
       ① **是什么情况** —— 这块板正开着，工具不让自动删（防误删）；
       ② **两个可选做法** —— **· 你自己删**（在 KaiBoard 界面里直接删）；**· 或切到别的画板，让我代删**（切走后我就能删）。
   - **`createBoard` 的 `parentId` 必须是已存在的文件夹**（否则 `PARENT_NOT_FOLDER`）。
   - **Agent 目前不能新建 / 重命名文件夹或画板**（暂无对应命令）→ 需要时**请用户先在界面上操作**，或走「新建替代 + 删旧的」变通并说明。
   - **通用纪律**：凡遇「**预期内的拒绝 / 降级**」，一律 **① 说明原因 ② 给下一步 ③ 不重复调同一条必失败的请求**。

8. **写操作前先确认页面已连上**：做写操作前，先确认 KaiBoard 侧显示**连接成功**。若显示连接失败，**立即停止发写命令** —— 否则命令可能落到另一个已连接的标签页/实例上（Agent 看到成功回包，但你眼前页面不动）。请用户按提示修复（打开页面 / 重新检测 / 刷新），确认后再继续。

9. **通道选择与降级规则 —— 绝不静默降级**：
   - **首选**：页面已连上 → **实时共绘**（画完即见）。
   - **次选**：页面没开或暂时连不上 → 走**离线写盘**通道。**必须明确告知用户**：这是异步通道，写入**不会实时出现在画布上** —— 左侧文件树会更新，当前画板需**切到别的画板再切回**才可见；且**不要**在用户正编辑该画板时写入（会被自动保存覆盖）。
   - **都不可用**：说明后端未就绪，引导用户修配置，**不要反复重试**。
   - **纪律**：降级**必须告知**用户当前走哪条通道及其后果；能用实时共绘时不要为省事主动走离线。

10. **不会截"整个界面"**：截图能力导出的是**画板元素的包围盒**，**不含**侧栏 / 顶栏 / 工具栏等应用 chrome。若要展示完整界面观感，正确做法是**把界面在画板里画出来**（窗口框 + 顶栏 + 侧栏 + 画布内容），再截图。

11. **多风格批量可选**：用户要"多画几张不同风格挑一挑"时，**每张风格各落一个新建画板**（保留原始那张不动，方便对比/挑选/组合），不要反复覆盖同一画板。

12. **推大图时分批**：元素数组过大时拆成多批推送（首批整板替换、后续批次追加），避免单次负载过大被截断。


## 画图范围（不止框架图）

这是 **KaiBoard 白板作图总入口**，不是"架构图生成器"。能画的不限于框架图：

- **草图 / 手绘 / 概念图**：高 `roughness`、留粗糙边、标注引线的自由表达。
- **标注插画 / 教学图解**：文字框标注 + callout + 代码块，讲"这里有什么、注意什么"。
- **框图 / 流程图 / 决策树**：结构 + 连接，靠箭头路由防穿框。
- **架构图 / 框架图**：结构图叠加分层（按受众决定画到哪层）。
- **线框 / UI 原型**：低保真示意 + 标注，信号"还是草稿"。
- **思维导图 / 头脑风暴 / 视觉笔记**：放射构图 + 通用视觉技法。

> **广义画图方法论**（风格档位 / 视觉技法 / 箭头路由 / 标注 / 构图 / 图类型→技法映射）见 `references/drawing-methodology.md` —— 任何画图任务先对照选技法，再落地。

## 素材感知构图（站在社区素材库肩膀上）

画架构图 / 系统设计图时，**优先用现成矢量图标，不要手搓矩形写标签**。Excalidraw 社区有 200+ 素材库（多数带组件级索引，可检索到单个图标），覆盖 AWS / Kubernetes / C4 / UML / Azure / 网络 / 安全 / 技术 Logo 等。本 skill 已把"检索 → 取件 → 沉淀 → 注入"做成薄胶水。

**架构原则**：
- **软件本体（KaiBoard 画图）= 本地优先、零联网** —— 产品哲学，不动摇。
- **Agent 交互层 = 天然联网** —— 素材库在线检索、按需取件是 Agent 的职责，不是软件的职责。
- **不预下载全量** —— 素材库在迭代，全量快照会过时且窄。
- **「我的素材」= 本地累积缓存** —— 搜到/取过的高频库沉淀到本地，之后离线也能用。

**用法**：
```bash
python scripts/lib_resolver.py --search "kafka"      # 跨源检索，返回候选库 + 命中组件
python scripts/lib_resolver.py --ensure "IT Logos"   # 把命中库下载并缓存到本地
```
取件后该库即被生成器自动识别：Mode B 直接按图标名嵌入；Mode A 取元素数组后实时注入画布。

> 🔴 **落地的坑与布局配方一律先看 `references/library-recipes.md`** —— 含 v1/v2 格式差异、
> 组件自带英文标签要丢、归一化四件事、**卡片图标放右侧**、出图前先跑 `geometry_check.py`。

**合规**：社区库多为 MIT。取用的素材请在帮助或产物中标注来源，保持开源诚信。

> **不随本仓分发任何素材库实体文件** —— 素材是第三方作者的资产，各有其许可；本仓只提供**在线检索与按需取件**能力，以及一份可检索的清单概览（`references/asset-catalog.md`）。
